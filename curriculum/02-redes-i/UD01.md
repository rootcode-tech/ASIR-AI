# ASIR-02 · UD01 — Modelos OSI/TCP-IP, encapsulación y herramientas de red

**Estado:** especificación curricular completa  
**Versión:** 0.1.0  
**Asignatura:** ASIR-02 · Redes I — Planificación y Administración de Redes

## 1. Objetivos

Al finalizar la unidad el alumno deberá ser capaz de:

- explicar la comunicación de red mediante los modelos OSI y TCP/IP;
- relacionar protocolos, unidades de datos y capas;
- comprender encapsulación y desencapsulación;
- diferenciar dirección física, lógica, puerto y nombre;
- explicar comunicación local y remota a alto nivel;
- utilizar herramientas básicas de diagnóstico;
- leer una captura de tráfico sencilla sin memorizar campos aislados.

## 2. Conocimientos previos

- ASIR-01 UD01-UD05 recomendadas.
- Aritmética básica y razonamiento técnico de ASIR-00.

## 3. Contenidos

### 3.1 Conceptos

- red, nodo, interfaz y enlace;
- LAN, WAN e Internet;
- modelo OSI;
- modelo TCP/IP;
- encapsulación;
- trama, paquete/datagrama y segmento;
- MAC, IP, puerto y nombre;
- cliente/servidor;
- protocolo;
- MTU a nivel conceptual;
- unicast, broadcast y multicast a nivel introductorio.

### 3.2 Procedimientos

- identificar capas implicadas en una comunicación;
- mapear protocolos habituales a capas;
- usar `ping`, `ipconfig`/`ip`, `tracert`/`traceroute`, `nslookup`/`dig`;
- capturar tráfico básico;
- identificar ARP, ICMP, DNS y TCP/UDP en una captura;
- separar problema de nombre, red, transporte y aplicación.

### 3.3 Diagnóstico

Errores comunes:

- confundir Internet con la Web;
- confundir IP con MAC;
- suponer que ping prueba todos los servicios;
- atribuir todo fallo a DNS;
- interpretar una capa como dispositivo físico fijo;
- usar el modelo OSI como lista de memoria en vez de herramienta de diagnóstico.

## 4. Teoría

El modelo por capas se utilizará como método de razonamiento:

`físico/enlace → red → transporte → aplicación`

Ante un fallo se preguntará qué capas funcionan y cuál es la primera que deja de hacerlo.

## 6. Ejercicios

1. Clasificar protocolos por capa.
2. Ordenar el proceso de encapsulación.
3. Interpretar cinco capturas simples.
4. Decidir qué herramienta usar según síntoma.
5. Explicar por qué un servicio puede fallar aunque ping responda.
6. Construir un árbol de diagnóstico por capas.

## 7. Laboratorio

### Objetivo

Observar una comunicación completa desde el host hasta una aplicación.

### Tareas

1. Consultar configuración de red.
2. Resolver un nombre.
3. Hacer ping.
4. Abrir una conexión web.
5. Capturar tráfico.
6. Identificar DNS, ARP/ND, IP y TCP/UDP.
7. Dibujar el flujo por capas.

### Validación

El alumno debe explicar cada paquete relevante sin depender de una plantilla.
